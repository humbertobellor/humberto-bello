<task type="auto" tdd="false">
  <name>task 2: add prefers-reduced-motion accessibility fallback</name>
  <files>src/styles/wolknitive-animations.css</files>
  <action>
    Append the following block at the end of `src/styles/wolknitive-animations.css`:

    ```css
    @media (prefers-reduced-motion: reduce) {
      *,
      *::before,
      *::after {
        animation-duration: 0.01ms !important;
        animation-iteration-count: 1 !important;
        transition-duration: 0.01ms !important;
      }
      .wk-reveal {
        opacity: 1;
        transform: translateY(0);
        transition: none;
      }
      .wk-anim-fade-left,
      .wk-anim-fade-right,
      .wk-anim-fade-scale,
      .wk-anim-fade-up,
      .wk-anim-fade-left-sm,
      .wk-anim-fade-up-sm,
      .wk-anim-bounce-y {
        animation: none !important;
        opacity: 1 !important;
        transform: none !important;
      }
    }
    ```

    The `0.01ms` approach disables animations while still allowing `prefers-reduced-motion` to be detected (unlike `animation: none` which can cause spec violations in some browsers). The `.wk-reveal` and animation class resets ensure elements are fully visible when motion is reduced.
  </action>
  <acceptance_criteria>
    - `src/styles/wolknitive-animations.css` contains `@media (prefers-reduced-motion: reduce)`
    - Inside the block: `animation-duration: 0.01ms !important;`
    - Inside the block: `.wk-reveal` with `opacity: 1; transform: translateY(0); transition: none;`
    - All 7 animation classes reset inside the block
  </acceptance_criteria>
</task>
