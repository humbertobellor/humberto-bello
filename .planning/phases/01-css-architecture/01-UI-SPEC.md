## Spacing Scale

No explicit spacing tokens exist in the current codebase. Spacing is handled via Tailwind utilities and inline `style={{}}` values. Phase 1 MUST define these tokens in `wolknitive-tokens.css`. The effective spacing values used in the existing design (extracted from inline styles and Tailwind classes):

| Token | Value | Usage |
|-------|-------|-------|
| `--space-2xs` | 4px | Tag inner padding, compact gaps |
| `--space-xs` | 6px | Icon gaps, small element spacing |
| `--space-sm` | 8px | Button padding-y, small gaps |
| `--space-md` | 12px | Tag horizontal padding, badge padding |
| `--space-base` | 16px | Default element spacing (1rem) |
| `--space-lg` | 22px–24px | Button padding-x, card padding (1.375–1.5rem) |
| `--space-xl` | 32px | Section padding (2rem) |
| `--space-2xl` | 48px–56px | Major section breaks (3–3.5rem) |
| `--space-3xl` | 80px–96px | Page section padding (5–7rem top, 6rem sides) |
| `--space-4xl` | 112px | Hero section padding (7rem top) |
| `--gap-grid` | 20px (1.25rem) | Grid gaps between cards (Tailwind `gap-5`) |

**Effective grid system** (from Tailwind classes to replace):
- `grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-5` → skills & experience card grids
- `grid grid-cols-2 md:grid-cols-3 gap-4 mb-16` → client showcase grid
- Responsive breakpoints: 768px (md), 1024px (lg)

**Exceptions:**
- Tag badges use non-8px values: `5px 14px`, `4px 9px`, `4px 10px` — preserve as-is
- Icon gaps use non-standard values: `0.375rem` (6px), `0.45rem` (7px), `0.3rem` (5px) — preserve as-is
- Touch targets: CTA buttons at `10px 22px` padding — exceed 44px minimum

### Scroll-Triggered Animations (replacing framer-motion)

**Source:** `src/components/FadeIn.tsx`

**Current behavior (must replace):**
- Element starts at `opacity: 0, y: 24px`
- On scroll into view (once, margin `-60px`): animates to `opacity: 1, y: 0`
- Duration: 0.55s, easing: cubic-bezier(0.22, 1, 0.36, 1)
- Per-element delay via `delay` prop (used in 5 FadeInSection instances — skill cards use staggered delays)

**Replacement target:**
- IntersectionObserver triggers CSS class addition (`.wk-anim-scroll-in`)
- CSS animation: `wkFadeSlideUpScroll` — opacity 0→1, y: 24px→0, 0.55s, same easing
- Staggered delays for grid children (skill cards: `i * 0.07s` delay, experience cards: no stagger)

### Nav Scroll Tracking (must preserve)

**Source:** `home.tsx:163-200`

- IntersectionObserver tracks which section is in view (hero, skills, experience, clients)
- Active nav link gets teal underline + teal text color
- Clicks scroll to section via `scrollIntoView({ behavior: "smooth" })`

### Hover Interactions (onMouseEnter/onMouseLeave → CSS :hover)

**Source:** 14 `onMouseEnter`/`onMouseLeave` handlers in home.tsx (QLT-03)

These handle:
- Nav link color changes (→ teal on hover)
- Card subtle elevation changes
- Tag badge background shifts
- CTA button color transitions
- Language switcher hover states

All MUST be replaced with CSS `:hover` pseudoclasses with smooth `transition` properties.

### Dark Mode (NEW — not fully defined)

**Current state:** Only `@custom-variant dark (&:is(.dark *))` in index.css and `--fg-on-dark` token.

**Phase 1 MUST author:**
- `@media (prefers-color-scheme: dark)` media query block
- Dark mode color overrides for all semantic tokens
- Dark mode shadow adjustments (lighter shadows for dark bg)
- Print stylesheet (`@media print`)

**Design direction for dark mode (from existing codebase clues):**
- Background: vellum-800 (`#1C1710`) or ink (`#14110B`)
- Surface: vellum-700 (`#2E261A`)
- Text: vellum-50 (`#FAF6EC`)
- Accent: teal-300 (`#5F8C86`) or teal-200 (`#95B5B0`) — lighter for contrast
- Rules: vellum-500 (`#6B5C3E`) or vellum-400 (`#9C8A64`)

**Phase 1 also MUST define dark mode colors — this is a creative decision within scope.** See user discretion for final dark palette.

## Design Gaps to Resolve in This Phase

These are decisions that REQUIRE user input during planning, surfaced here for transparency:

1. **Dark mode colors**: The codebase has a `@custom-variant dark` stub but no actual dark mode color overrides. What dark palette should Phase 1 author? (Recommended: invert vellum scale — bg `#1C1710`, surface `#2E261A`, text `#FAF6EC`, teal accent lighter to teal-300 `#5F8C86`)
2. **Print stylesheet**: What should the print output look like? (Recommended: remove decorative elements, one-column layout, black text on white)
3. **Spacing token naming**: Should spacing tokens follow `--space-{name}` pattern or remain implicit? (Recommended: `--space-{name}` for clarity)
